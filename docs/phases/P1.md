## Goal
One seeded run, paid end to end on Arc testnet through the real path: obligation -> gate -> payment agent -> Circle wallet -> `PayrollGuard.pay` -> Arc receipt matched -> SETTLED. Started from scripts or localhost only (rule 41). Also the minimum demo fallback (`PRD.md` §12).

## Agent work (backend, Ponytail `full`; UI without Ponytail)
1. `contracts/`: `PayrollGuard.sol` per ARCHITECTURE §14.2 + Foundry tests (ERC-20 mock); `scripts/export-guard-abi.ts`.
2. `src/core/money`, `ports`, minimal `engine` (base salary, trace, `calculation_hash`), `payments` (obligation, `gate.ts` with `GatePass`, payment agent, settlement matching).
3. `supabase/migrations`: only the tables P1 needs (companies, workers, runs, calculations/lines, obligations, batches, payment attempts, audit) with `company_id`, RLS, CHECKs and unique keys; `seed.sql` (synthetic, labelled).
4. `src/server`: `log.ts` (redacting), `db/` repositories, `circle/` (wallets, `guard-owner.ts`), `arc/` viem reader (chain 5042002 check), `rails/arc-usdc-rail.ts`.
5. `scripts/`: `setup-wallets.ts`, `create-users.ts`, `check-balances.ts`, deploy guard, run the seeded payment.
6. UI last (follow `DESIGN.md`, set Sofia Sans + tokens first): crude dashboard and `runs/[runId]` page with the arcscan link.

## Done when
1. `forge test` in `contracts/` → passes, including S01–S03 cases.
2. `npm run lint`, `npx tsc --noEmit`, `npm test`, `npm run test:invariants` → exit 0.
3. Seeded run: script pays 1 obligation (≤ 100 USDC total) on Arc testnet; obligation ends SETTLED from an independent receipt match (S30); arcscan link opens.
4. Repeating the payment script does not pay twice (guard + idempotency).
5. Chain on-chain data check: only net amount, recipient, hashed keys (rule 30).
6. Browser check: dashboard and run page show the run, trace and tx link on localhost.
7. Security rows below `verified`, or `unverified` with a reason.
8. `PROGRESS.md` updated; second-agent review done (P1); one commit, PR, CI green, squash-merge.
