# P3 — Data + AI (Oct 4–5; may start earlier)

Status: **built 2026-10-02 on branch `p3-data-ai`, NOT committed; awaiting the user's browser check.** Plan approved by the user the same day. The waitlist (`W`) is the user's and is not touched in P3.

## Goal
Messy policy and CSV data become a reconciled, calculated SIMULATION run with a variance report. AI proposes, validators check, humans approve. Ends at `CALCULATION_VALIDATED`; no payments (P4). Acceptance criteria 1–9 and 26 of the PRD.

## Build slices (each ends green before the next)
1. **AI core + policy → config.** `core/ai` (ports, validate–repair pipeline, `AIExecution`), `core/ai/inputs` (strict builders), `core/validation`, `server/ai/openrouter.ts`, `core/integrations` (capabilities, `csv_upload`, provenance schema). `/configuration`: policy clauses → AI rules citing clauses → validation log → HR approval (existing config lifecycle).
2. **Import.** `core/ingest` + browser anonymiser (parse, column mapping, W-codes, passphrase-encrypted name key file), migration for `import_batches`, `schedules`, `timesheets`, `leave_records`, `actual_payments` (provenance NOT NULL, encrypted amounts), import API + `/import`.
3. **Reconciliation + exceptions.** `core/reconciliation` (4 categories, match status), AI classification intake, `exceptions` evidence, single and bulk resolve, `/exceptions`.
4. **Calculate + variance.** Wire reconciled snapshot → existing engine (`CALCULATED` → `CALCULATION_VALIDATED`), `core/variance`, `variance_findings`, payroll review page with trace and variance.
5. **Table view + polish.** Reusable table view (columns, sort, filter, search, match status, totals, export, side panel), applied to workers, import results, exceptions. AI view proposals last (first cut). `/privacy` data note, `scripts/delete-company.ts`, model eval.

Backend slices use Ponytail `full`, then `ponytail-review`. UI last, per `DESIGN.md` and `docs/pages.md`.

## Decisions (change any before I start)
1. **Order:** slices as above, cheapest cut first: AI view proposals → saved views → side panel → model-eval table (PRD §12).
2. **CSV layouts:** one file per import type, chosen on `/import`: timesheets, leave, actual paid. **Cut (2026-10-02):** workers/compensation import (workers are added on `/workers`) and schedules import (the config holds scheduled hours). Imports are accepted until reconciliation starts. Column mapping is human-confirmed; AI mapping suggestions see headers only.
3. **Re-import / edits:** natural key + content hash. Same record again → no change. Changed record → new evidence version; runs past `READY_FOR_CALCULATION` keep their snapshot (S48).
4. **AI worker setup** (P2 decision 10): the assistant proposes a worker (code, pay type, rate) from typed fields only, no names; a human approves in the existing `/workers` flow. Cuttable after slice 3.
5. **Model (decided by the eval, 2026-10-02):** default `google/gemini-2.5-flash-lite` (6/6 accepted on the final prompt, no flags), fallback `openai/gpt-oss-120b` (2/3). Rejected: `z-ai/glm-5.3-flash` (declined 5 of 6 real runs and took 12-54 s), `deepseek/deepseek-v4-flash`, `gpt-4.1-nano`, `gpt-5-nano`, `mistral-small` (mostly declined or unavailable under the no-retention routing). Both are config (`OPENROUTER_MODEL`, `OPENROUTER_FALLBACK_MODEL`). The eval also exposed prompt and validator gaps, now fixed and tested (a model set the overtime threshold to 0; flagged now). Tests use a fake provider; CI never calls OpenRouter.
6. **AI outage:** policy and classification fall back to `NEEDS_HUMAN_REVIEW`; exceptions are still raised deterministically.
7. **Hours bucketing:** ISO-week overtime from P2 decision 1 is implemented here in reconciliation.
8. **Demo company:** seeded with an approved config and finished runs so it works with the AI down.
