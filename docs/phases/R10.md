### R10.1 review note: approved recovery clarification (owner 2026-10-13)
Owner approved the prepared narrow clarification on 2026-10-13. Rule 26 and S28 now carry the exact text below; ARCHITECTURE14.6 is synchronized. This documentation change does not execute recovery, authorize a replacement command or claim provider acceptance.

**Approved ESSENTIALS rule 26:** Never retry blindly. Save the attempt and idempotency key before calling Circle. After timeout, crash or UNKNOWN, reconcile Arc first and query Circle when its transaction ID is available. If Arc reports paid, only independently verified receipt settlement may proceed. If Arc reports unpaid, recovery must pass the gate again, including the kill switch. A stored Circle transaction ID is tracked, never resubmitted. If no Circle ID was persisted, recovery may continue the original command only with the original obligation, saved attempt/refId and idempotency key and unchanged business payload: agent wallet, guard, `pay(bytes32)` obligation key and fee; approved amount and recipient remain bound by the gate and guard. UNKNOWN stays explicit until authoritative evidence resolves it. Recovery never automatically creates a replacement attempt or key; any replacement requires proven terminal failure, Arc unpaid and separate authorization. SETTLED always requires the independent Arc receipt match.

**Approved S28 recovery sentences (matrix and AI checks retained):** Unknown remains explicit. After Arc reconciliation, an unpaid obligation may continue the original command without a stored Circle ID only through a fresh gate, including OFF, using the same saved attempt/refId, idempotency key and unchanged business payload. A stored Circle ID is tracked without resubmission. Terminal Circle failure with Arc unpaid becomes PAYMENT_EXCEPTION, with no automatic replacement attempt/key. Any separately authorized replacement requires proven terminal failure and Arc unpaid; Circle COMPLETE alone never settles.

**Source limits and review evidence:** `src/core/payments/agent.ts` (`resumeObligation`, `track`, `settle`), `src/core/payments/gate.ts` and `src/server/rails/arc-usdc-rail.ts` support this command-level distinction. Installed Circle SDK 10.8.1 generates RSA-OAEP entity-secret ciphertext for each request; ephemeral ciphertext may differ while the business payload stays identical. This is not a claim about byte-identical HTTP bodies or proven live-provider deduplication. Current recovery can create the original attempt after a crash before its persistence; this is not a replacement attempt, and no prior submission should exist in that case. Owner R3.7 funded evidence and runbook review remain prerequisites to R10.1 closure.
